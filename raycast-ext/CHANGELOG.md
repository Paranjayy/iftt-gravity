# Gravity Hub — Changelog & Architecture Handoff

This document is the running record of what's been built, why, and the gotchas
the next maintainer (human or AI) needs to know to keep moving forward.

The handoff target is a "successor" — anyone reading this should be able to
pick up the project without re-discovering the same potholes.

---

## Project at a glance

`gravity-hub` is a 14-command Raycast extension that acts as a local-first
mission control for the user's home IoT hub (AC, smart bulb, SmartThings,
Solis solar, energy, Telegram). It runs entirely off the local Mac; the bot
it talks to (`src/lib/bot.ts`) is a separate Bun service on `127.0.0.1:3030`.

The extension is built with `bun run build` (from `raycast-ext/`) and lives
at `~/.config/raycast-x/extensions/gravity-hub/` for the Raycast X (Beta)
flavor, and `~/.config/raycast/extensions/gravity-hub/` for the stable
flavor. The `bunx @raycast/api@latest build` only writes to the flavor
that's currently being targeted (see "Potholes" below).

There are also 10 `*.sh` script commands in `raycast-ext/` under the
`Gravity Tools` packageName — these run as plain shell scripts in Raycast
(start/stop the hub, backups, etc.) and have their own icons at the script
level (`./hub.png`, etc.).

## Architecture decisions

### Master icon & per-command icons
- Master: `raycast-ext/assets/icon.png` (1024×1024)
- Per-command: `raycast-ext/assets/commands/<name>.png` (512×512, tinted variants)
- Generated by `raycast-ext/scripts/make-command-icons.py`
- **Source of truth in `package.json`**: `icon: "commands/<name>.png"` (the
  Raycast bundler auto-resolves relative to `assets/`)
- The build copies `assets/` to the output extension dir

### Optimistic bulb state
The server doesn't expose WiZ pilot state over HTTP. The extension
maintains local optimistic state (brightness, temp, color, sceneKey) in
`useState` + persists to `LocalStorage` under key `gravity-bulb-state`.
Real power state is read from `state.stats.light.status` (server-tracked
`"on"`/`"off"` string).

### Polling & race-guard
- `2s` polling on `hub_pulse`, `control`, `bulb-control-detail`
- `3s` on `hub_pulse`
- `8s` on `recent_activity`
- All use `AbortController` with 4-5s timeouts
- `fetchSeq` race-guard to drop stale responses

### Custom timer Forms
- Primary action is `Action.Push target={<FormComponent/>}` (NOT a stub
  `onAction: () => return` — that was an old bug, see potholes)

### `iftt-clone.sh` now uses preload shim
- `iftt-clone.sh bot` — fast bot-only restart
- `iftt-clone.sh archive` — fast archive-only restart
- default (no arg) — full stack (web + bot + archive)

## Bot endpoints (the API the extension talks to)

All on `127.0.0.1:3030`. CORS is `*` for everything.

| Method | Path                              | Purpose                          |
|--------|-----------------------------------|----------------------------------|
| GET    | `/status`                         | Full hub state JSON              |
| POST   | `/control/schedule/add`           | Add a schedule entry             |
| GET    | `/control/schedule/list`          | List all schedules (w/ id)       |
| GET    | `/control/schedule/clear`         | Wipe all schedules               |
| POST   | `/control/schedule/remove`        | Remove one schedule by id        |
| POST   | `/control/bulb/timer?mins=N`      | Auto-off in N minutes            |
| GET    | `/control/restart`                | Soft restart of hub state        |
| GET    | `/scene/<name>`                   | Activate a scene                 |
| GET    | `/system/lock`                    | Lock Mac screen                  |
| GET    | `/archive/sync`                   | Sync archive vault               |
| GET    | `/archive/notes/list`             | Notes index                      |
| POST   | `/archive/jot`                    | Save a quick note                |
| ...    | `/control/ac/...`, `/control/bulb/...`, etc. | Device control |

Schedule jobs shape:
```json
{
  "id": "job-1783776386778-3x3l1s",   // stable, set on add
  "time": "06:30",
  "action": "bulb_warm",
  "days": "monday,wednesday,friday",   // OR "daily" | "weekdays" | "weekends"
  "lastRun": "",
  "weekdaysOnly": false                 // legacy field, set for weekdays only
}
```

The scheduler (in `src/lib/bot.ts` `GravityScheduler.check()`) handles:
- `daily` → fires every day
- `weekdays` → Mon-Fri (getDay() 1-5)
- `weekends` → Sat-Sun (getDay() 0 or 6)
- `monday,tuesday,...` → comma-separated list of full day names

### Round 11 (this PR): URL → Markdown command
- **NEW 16th command: `URL → Markdown`** (registered as `convert_link`)
- **Smart title extraction** with fallbacks:
  1. `og:title` (Open Graph, gold standard, works on Twitter, LinkedIn, Reddit)
  2. `twitter:title` (Twitter-specific)
  3. `<title>` tag (works on GitHub, blogs, etc.)
  4. **Bot-block detection** — rejects "Please wait", "Just a moment",
     "Verifying", "Cloudflare" etc. so we don't keep the placeholder
  5. URL-slug fallback — extracts meaningful path segments and titlecases
     them (e.g. `quora.com/Who-is-a-better-speaker-Sadhguru...` → "Who is a better speaker Sadhguru...")
- **User-agent spoofing** — sends real-browser UA so we don't get SPA shells
  from Twitter, LinkedIn, etc.
- **4 output formats** — Numbered (default, `1. [Title](url)`),
  Bullet (`- [Title](url)`), Bare (`[Title](url)`), Timestamped
  (`- 2026-07-23 22:00 [Title](url)`)
- **Bulk paste support** — paste a whole block of text, all URLs auto-detected
- **Smart dedup** — URLs converted in the last 24h are skipped automatically
  (with toast: "3 URLs skipped, already in history")
- **Clipboard auto-read** — `Convert Clipboard` action reads current clipboard
- **History** (LocalStorage `homepulse-url-history`, capped at 200 entries):
  - Per-item actions: Copy, Preview, Re-convert (refresh titles),
    Re-convert as different format, Copy raw input, Delete
  - Search by URL or output text
  - Export Full History (groups by day, copies to clipboard as markdown)
  - Clear All History
- **Bot endpoint unchanged** — the legacy `/archive/convert/md` endpoint
  stays as a fallback; the new command does client-side conversion
  for speed and to use the new title-extraction heuristics
- New icon: `commands/convert_link.png` (sky blue, generated by the
  Python icon script)

## Potholes (read this before you change anything)

### 1. Raycast flavor split (icon issue)
`bunx @raycast/api@latest build` writes to:
- `~/.config/raycast/extensions/<name>/` for stable Raycast
- `~/.config/raycast-x/extensions/<name>/` for Raycast X (Beta)

If you have BOTH installed, only one gets the new build. The screenshot
in the user's report showed old icons because they were looking at the
stable Raycast's May 9 build, but the latest build was going to
`raycast-x/`. **Fix**: either uninstall one, or run
`RAY_Target=x bunx @raycast/api@latest build` to target the X flavor.

### 2. Bun + debug@4 CJS interop bug
Bun crashes the bot on startup with:
```
TypeError: debug_1.default is not a function
```
**Fix**: preload `scripts/bot-preload.cjs` which monkey-patches
`Module.prototype.require` to normalize debug@4's `.default` export.
Always start the bot with:
```bash
bun --preload /Users/paranjay/Developer/iftt/scripts/bot-preload.cjs src/lib/bot.ts
```
`iftt-clone.sh` does this by default. Don't run `bun src/lib/bot.ts` directly.

### 3. WiZ bulb unreachable from current network
`192.168.29.252:38899` is unreachable. Any scene that hits WiZ-direct
(`/scene/tv`, `/scene/dinner`, `/scene/matrix`, `/scene/power_nap`)
returns "Something went wrong!" because the triggerScene hardcoded cases
don't gracefully handle missing miraie AC adapter (also offline).
**Not a code bug** — environmental.

### 4. Reserved Raycast shortcuts
`cmd+k`, `cmd+t` etc. are reserved by Raycast. The dev.log fills with:
```
The 'shortcut' prop provided to the Action 'X' is reserved by Raycast and
has been removed.
```
The action still works, just without the keyboard shortcut. To avoid the
warning, use `cmd+shift+<key>` or pick less common combos.

### 5. `<List>` only accepts List children
Dev.log shows:
```
A `List` only accepts `List.EmptyView`, `List.Item` and `List.Section`
children. Ignoring `ray-menu-section`.
```
This happens when you wrap a List in another JSX element. Always return
`<List>` directly, not `<List>...</List>` wrapped in a fragment or div.

### 6. `package.json` icon paths are relative to `assets/`
Both:
```json
"icon": "icon.png"
"icon": "commands/smartthings.png"
```
work, because the build auto-prepends `assets/`. Don't add the `assets/`
prefix manually — you'll get `assets/assets/X.png` which doesn't exist.

### 7. ESLint has no config
`bun run lint` fails with "ESLint couldn't find a configuration file".
Pre-existing. `bun run build` is the source of truth; lint is optional.

### 8. Next.js dashboard on :3000 is NOT auto-started
`iftt-clone.sh` starts it, but the user's bot-only restart won't.
`recent_activity` and `hub_diagnostic` will show "FAIL" for the
`http://127.0.0.1:3000` probe until the user runs the full stack.

## How to develop

```bash
# 1. Make sure hub is running
cd /Users/paranjay/Developer/iftt && ./iftt-clone.sh

# 2. Live-reload extension (auto-rebuilds on save)
cd /Users/paranjay/Developer/iftt/raycast-ext
bun run dev
# Cmd+R in Raycast to reload after dev mode picks up changes

# 3. Manual build (one-shot)
bun run build

# 4. Restart bot only (after server-side changes)
cd /Users/paranjay/Developer/iftt && ./iftt-clone.sh bot

# 5. Restart everything
./iftt-clone.sh
```

## Where to look first when something breaks

1. **Bot is down** → `tail -50 /tmp/gravity-bot.log`. If `TypeError: debug_1.default`
   → preload shim not being loaded (check `iftt-clone.sh`)
2. **Icons missing in Extensions list** → check both
   `~/.config/raycast/extensions/gravity-hub/` AND
   `~/.config/raycast-x/extensions/gravity-hub/`. Whichever is stale needs
   a `bun run build` (or restart Raycast)
3. **Schedule form says "old bot"** → bot not restarted since the endpoint
   was added. Run `./iftt-clone.sh bot`
4. **Build error after editing a `.tsx`** → check the tsc errors at the
   bottom. Common: missing imports (`Action`, `Icon`, etc.)
5. **WiZ bulb scene doesn't work** → expected, bulb is offline. Use
   `/control/bulb/color?temp=X` instead (HTTP path that doesn't need bulb
   for the optimistic state update)
